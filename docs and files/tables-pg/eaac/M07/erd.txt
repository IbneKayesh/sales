====================================================================================================
3. CORE ENGINE LIFECYCLES & PROCESSING PIPELINES
====================================================================================================

----------------------------------------------------------------------------------------------------
3.1 ATTENDANCE PROCESSING PIPELINE
----------------------------------------------------------------------------------------------------

  Biometric Device Punch
            |
            v
   [tmhb_atnlg] (Raw Logs - punch_datetime only, no IN/OUT)
            |
            v
   Find Employee Duty Schedule [tmhb_emprd] / Default Shift [tmhb_empdf]
            |
            v
   Load Applicable Shift [tmhb_wkshf] (Start, End, Grace In/Out, Cross Midnight)
            |
            v
   Determine Duty Date & Pair First Punch (IN) / Last Punch (OUT)
            |
            v
   Calculate Worked Mins, Late Mins, Early Out Mins, Overtime Mins
            |
            v
   Check Leaves [tmhb_lvapp], Holidays [tmhb_hlday], Weekly Offs [tmhb_wkofd]
            |
            v
   Generate Processed Daily Attendance [tmhb_attnd]
            |
            +---> If Missing / Anomalous Punch ---> [tmhb_atnxc] (Exception)
            |                                             |
            |                                             v
            |                                   [tmhb_atcrq] (Correction Request)
            |                                             |
            +---------------------------------------------+

----------------------------------------------------------------------------------------------------
3.2 LEAVE PROCESSING & ENTITLEMENT LIFECYCLE
----------------------------------------------------------------------------------------------------

  1. Employee submits Leave Application [tmhb_lvapp] for Date Range
  2. System breaks down dates into [tmhb_lvdys], checking Weekly Off / Holidays
  3. System reserves days in [tmhb_lvbal] (pending_days += days, remaining_days -= days)
  4. Routing through Workflow Steps [tmhb_wfstp] -> Supervisor Approval [tmhb_lvapr]
  5. If Approved:
     - status = 'APPROVED'
     - [tmhb_lvbal]: used_days += days, pending_days -= days
     - [tmhb_lvtxn]: Creates audit entry (ttype='USED', reference='LEAVE_APPLICATION')
     - Automatically updates Attendance Sheet [tmhb_attnd] (is_leave=true, payable=true/false)
  6. If Returned:
     - status = 'RETURNED'
     - Employee can edit dates/reason and resubmit
  7. If Rejected:
     - status = 'REJECTED'
     - [tmhb_lvbal]: pending_days -= days, remaining_days += days

----------------------------------------------------------------------------------------------------
3.3 PAYROLL PROCESSING & FINALIZATION LIFECYCLE
----------------------------------------------------------------------------------------------------

  1. Open Payroll Period [tmhb_pyprd] for Cycle [tmhb_pycyc] (e.g. 1st - 30th)
  2. Run Payroll Batch [tmhb_pyrun]:
     - Aggregate Attendance from [tmhb_attnd] (Scheduled, Present, Leave, Holiday, Off, Absent)
     - Calculate Total Payable Days & Overtime Minutes
     - Fetch Employee Base Salary [tmhb_empsl] & Structure [tmhb_slstr] / [tmhb_slscf]
     - Compute Earnings Components (Basic, Allowances, Overtime Pay)
     - Compute Deductions Components (Absent Deductions, Tax, Advances)
     - Apply Approved Adjustments [tmhb_pyadj] (Arrears, Bonuses, Penalties)
     - Write Summary to [tmhb_empyr] and Breakdown to [tmhb_pyrcm]
  3. Review & Approval -> Status changed to 'APPROVED'
  4. Finalization & Lock -> Status changed to 'FINALIZED' / 'LOCKED' (Data becomes Immutable)
  5. Generate Employee Payslips [tmhb_pslip]
